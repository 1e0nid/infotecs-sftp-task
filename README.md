# SFTP Domain Client

Тестовое задание для стажера (направление "Автотестирование Java").

Суть: консольный клиент, который подключается по SFTP к серверу, читает файл
с парами "домен - IP" (JSON) и дает над ним разные операции. Плюс автотесты
на TestNG.

## Что делает клиент

После запуска просит адрес, порт, логин и пароль от SFTP. Если подключение
успешное - показывает меню:

1. Вывести все пары домен-адрес (отсортировано по домену)
2. Найти IP по домену
3. Найти домен по IP
4. Добавить новую пару домен-адрес (с проверкой на уникальность и что IP
   валидный IPv4)
5. Удалить пару по домену или по IP
6. Выйти

Файл на сервере - обычный JSON вида:

```json
{
  "addresses": [
    { "domain": "first.domain", "ip": "192.168.0.1" }
  ]
}
```

## Сборка

Нужна Java 8 и Maven. Внешних библиотек кроме TestNG и клиента для SFTP не
использовал (по условию задания).

```
mvn clean package
```

После сборки jar-ник будет в `target/`.

## Как запустить

```
java -jar target/<имя-jar-файла>.jar
```

Дальше просто вводишь адрес сервера, порт, логин, пароль - и работаешь с
меню.

## Тесты

Тесты лежат в `src/test/java/org/example/tests`:

- `JsonParserTest` - проверка парсинга/сериализации JSON-файла с адресами
- `IpValidatorTest` - проверка валидации IPv4
- `DomainServiceTest` - логика поиска/добавления/удаления пар домен-IP
- `ClientConsoleIntegrationTest` - интеграционный тест через консоль
  (эмулирует ввод пользователя)
- `TestSuiteRunner` - запускает всё вместе

Плюс есть expect-скрипт `scripts/expect/list_domains.exp` - он гоняет
реальный консольный клиент и проверяет, что вывод меню корректный.

Запуск тестов через TestNG:

```
mvn test
```

или конкретный suite:

```
mvn test -DsuiteXmlFile=testng.xml
```

(`testng-integration.xml` - отдельно интеграционные тесты, если нужно
гонять их отдельно от юнит-тестов)

## Структура проекта

```
pom.xml
scripts/expect/list_domains.exp
src/test/java/org/example/tests/
    ClientConsoleIntegrationTest.java
    DomainServiceTest.java
    IpValidatorTest.java
    JsonParserTest.java

testng-integration.xml
```

## Немного по тестам (почему так)

Старался покрыть и позитивные, и негативные сценарии: валидный/невалидный
IP, добавление дубликата домена/IP, поиск несуществующего домена/IP и т.д.
Expect-скрипт добавил дополнительно, чтобы проверить именно консольный
интерфейс целиком, а не только внутреннюю логику
